# itgmania-harness-rs

A Rust command-line harness for generating expected values with ITGmania's
own parsing and calculation code.

This project is a replacement for `../itgmania-reference-harness`. Its job is
to expose ITGmania as an oracle, not to reproduce ITGmania algorithms in Rust.

## Oracle contract

- ITGmania loads the simfile and calculates every ITGmania-owned result.
- Rust selects inputs, calls the native bridge, writes machine-readable output,
  and manages baseline files.
- Rust must not reimplement parsing, timing, radar, tech-count, hash, or chart
  selection behavior.
- If ITGmania cannot produce a requested value, the harness reports an error or
  an explicit unavailable value. It must not silently calculate a substitute.
- Theme-owned results are produced by running the checked-in theme Lua unchanged
  and are labeled separately from engine-owned results.

### Raw numeric values

Numeric output represents the value returned by ITGmania, not ITGmania's UI
formatting of that value.

- Native `float` and `double` values cross the bridge without rounding.
- The output layer uses a shortest round-trip number representation.
- There is no fixed decimal precision, padding, or decimal-place normalization.
- Strings returned by an ITGmania API remain strings and are not parsed and
  regenerated by Rust.
- Baseline comparisons treat JSON numbers as values, not as decimal strings.

For example, the old harness forces some timing values through
`fixed`/`setprecision(6)`. Raw native captures retain their full precision;
the optional RSSP report export preserves the old CLI's serialization contract.

## Source checkout and pins

Initialize the two source submodules before building:

```bash
git clone https://github.com/pnn64/itgmania-harness.git
cd itgmania-harness
git submodule update --init
git -C vendor/itgmania submodule update --init extern/ogg extern/vorbis
cargo build
cargo run -- doctor
```

For an existing clone, run `git submodule update --init` after pulling a change
that updates either source pin. The harness records exact commits in Git:

- `vendor/itgmania`: upstream ITGmania v1.2.0,
  `5c737928d93778c2c9f68e276052b220b43a468f`.
- `vendor/simply-love`: upstream Simply Love 5.9.0,
  `dd06138b15492f4136796dfe4b6708ced0f7b9eb`.

These trees match the engine and theme resources from the previous workspace
after normalizing line endings. The engine source pin is deliberately retained
at the baseline version. Simply Love is separate because ITGmania v1.2.0's
nested theme pin is 5.8.0, while the existing harness baselines use 5.9.0.

The harness uses the engine's checked-in Lua, JSONCPP, PCRE, miniz, noteskins,
and fallback resources. Native music duration queries also require the pinned
`extern/ogg` and `extern/vorbis` submodules. Initialize these explicitly with
`git -C vendor/itgmania submodule update --init extern/ogg extern/vorbis`; the
remaining nested submodules are unnecessary. Linux/WSL still needs the system packages listed
below. `ITGMANIA_ROOT` remains available for another engine source checkout;
set it before invoking Cargo to compile that revision. `doctor --itgmania-root`
inspects a tree without changing the source compiled into the binary.

To update a pin deliberately:

```bash
git -C vendor/itgmania fetch origin tag NEW_TAG
git -C vendor/itgmania checkout --detach NEW_TAG
cargo test
git add vendor/itgmania
```

Review regenerated baselines before committing a source update. Update
`vendor/simply-love` the same way when changing the theme reference; do not use
`git submodule update --remote` as part of normal builds.

The default tests use the pinned sources and checked-in fixtures. Tests that
need the external Lua-song or DeadSync font corpus are explicitly ignored;
run those by name with `-- --ignored` when their documented sibling directories
are available.

## Current status

The first native slice is working on Windows and Linux/WSL. The Rust CLI
compiles the required ITGmania sources through Cargo, loads `.sm` and `.ssc`
files with ITGmania's loaders, and exports:

- song and chart metadata;
- the exact `STEPSTYPE` string retained by `Steps`, plus native steps-type and
  difficulty enum codes;
- meter and actual/display BPM ranges;
- timing offsets;
- all native timing segments, including rows, beats, values, and labels;
- native note rows, note types, durations, attacks, and keysounds;
- per-player radar values and all native tech-count categories.
- native GrooveStats hashes and versions, first/last note seconds, notes and
  NPS per measure, and peak NPS for both players;
- optional unchanged Simply Love chart parsing, hashes, stream sequences,
  breakdown strings, and formatted display BPMs, labeled separately;
- requested-text bitmap-font page, mapping, and glyph geometry from
  ITGmania's native `Font` implementation.
- bundled noteskin discovery, fallback-merged metrics, typed metric values,
  and element/redirect paths from ITGmania's native `NoteSkinManager`.
- native song background/foreground layer order and scheduling metadata, with
  Lua entrypoint resolution for a complete song corpus.
- deterministic song-Lua semantic traces executed in-process by ITGmania's
  bundled patched Lua runtime: actor definitions and layer order, commands,
  actor API calls, callbacks, messages, modifiers, tweens, and draw order.
- native Actor, ActorFrame, Sprite, tween, effect, matrix, and projection
  conformance traces, including the final vertices submitted for drawing.

Manifest-driven baseline generation, read-only verification, and standalone
JSON diffing are also working. Semantic song-Lua baselines do not launch an
ITGmania executable or require an installation; they read the checked-out
source and song corpus directly. See [PLAN.md](docs/PLAN.md).

## Actor and tween conformance

`actor-conformance` runs a small deterministic actor tree through ITGmania's
compiled `Actor`, `ActorFrame`, `Sprite`, tween, effect, matrix, and display
base code. It is entirely in-process and headless: it does not launch an
ITGmania executable, create a window, or modify the ITGmania source tree.

```powershell
.\target\debug\itgmania-harness-rs.exe actor-conformance `
  fixtures\actors\transform-projection.json `
  --out transform-projection.itgmania.json
```

Every requested sample contains the complete current/start/destination tween
state, every remaining native queue entry and its interpolation fingerprint,
the effect clock and effect-applied state, local/parent/world/view/projection
matrices, actor draw sequence, and every primitive submitted by `Sprite`.
Vertices retain local, world, view, clip, normalized-device, and logical-screen
positions together with raw/transformed UVs and exact 8-bit vertex colors.
The fixture output also records child order before and after native stable
`SortByDrawOrder` processing.

The checked-in micro-fixtures under `fixtures/actors` cover actor behaviors independently:

- `tween-queue.json`: queued interpolation, sleep, targets, and queue removal;
- `scheduled-fade.json`: fade queues appended by a native command at dispatch;
- `queued-reset-clock.json`: accelerated motion followed by zero-time resets
  on native float frame boundaries;
- `tween-curves.json`: native linear, accelerate, decelerate, spring, and
  one-dimensional Bezier interpolation;
- `transform-projection.json`: nesting, rotation order, alignment, base zoom,
  skew, nonuniform scale, and perspective projection;
- `crop-fade-color.json`: native crop/fade subdivision, UV transforms,
  corner diffuse colors, glow passes, and submitted geometry;
- `effects-vibration.json`: effect clocks, color effects, wag, pulse, spin, and
  reproducibly seeded native vibration;
- `draw-order.json`: native stable post-`DrawOrder` sorting and actual draw
  sequence.

Fixture samples must be non-negative and ascending because a scene is advanced
continuously, just as it is during gameplay. `random_seed` makes ITGmania's
native vibration offsets reproducible. The standard logical screen is 640x480;
`screen`, `bpm`, per-frame `camera`, and effect clock settings can be overridden
in the fixture. Regenerate and compare the JSON oracle output from a native
DeadSync test to isolate primitive-level parity failures before using song-wide
traces.

`broadcast-subscriber-order.json` uses native `MessageManager` dispatch with
two subscribers writing the same child. Its final child x is exactly 1 or 2:
ITGmania stores subscribers in a pointer-ordered set, so allocation can change
which handler runs last. An unsubscribed actor receives no broadcast. This
input intentionally has no single golden output. The song Lua semantic host
uses the linked native manager with one subscriber identity per Lua actor.
`message_order` records each identity's pointer rank, and `message_dispatches`
records the delivered actor IDs for every broadcast, including unsampled
updates. Parameter tables stay in the song VM so shared table identity and
nested broadcasts survive the bridge. Allocation order is capture context,
not a guaranteed parent/child rule. Older tree-order captures cannot establish
parity for handlers that share mutable state.

## Font probes

`font` loads a theme bitmap font through ITGmania's `Font::Load` and reports
the native result for each character in the requested text. If `--text` is
omitted, the command probes ASCII letters and digits.

```powershell
.\target\debug\itgmania-harness-rs.exe font `
  "vendor\simply-love\Fonts\Miso\_miso light.ini" `
  --text "Ag 1"
```

The font path may be an `.ini` or `.redir` beneath an ITGmania theme's
`Fonts` directory. The harness infers that theme's font root and uses the
adjacent `_fallback/Fonts` tree for native font imports when present; otherwise
it uses `Themes/_fallback/Fonts` from the source tree compiled into the harness.

Output includes the resolved font and fallback roots, font-wide height and
line spacing, line measurements, default stroke color, and an entry for every
requested glyph. Glyph entries retain ITGmania's page/frame selection,
fallback decision, pen position, advance, dimensions, shifts, and texture
rectangle. `observed_pages` contains only pages selected by the requested
text, so use a representative character set when investigating coverage.

This first slice is headless: ITGmania performs font parsing, imports,
character mapping, and `FontPage` geometry, while the harness supplies PNG
dimensions in place of a GPU texture upload. The output separately records
source, image, and backing-texture dimensions so that resolution hints,
`doubleres`, frame grids, and power-of-two padding remain visible. It does not
yet compare GPU sampling or rendered pixels, and non-PNG font pages fail
explicitly rather than using a substitute image.

### Portable font baselines

`font-baseline` recursively loads every `.ini` below a Fonts directory and
writes one portable JSON fixture per font plus `_manifest.json` provenance.
It probes every BMP character that ITGmania reports as complete, astral
characters authored in `Line` mappings, the default glyph, and a missing-glyph
sentinel. Paths are normalized relative to the supplied Fonts directory and
texture rectangles are stored in image pixels, so the committed fixtures can
be compared by native Rust tests on Windows or Linux without loading the C++
oracle at test time.

From this workspace on Windows:

```powershell
.\target\debug\itgmania-harness-rs.exe font-baseline `
  ..\deadsync\assets\fonts `
  --out ..\deadsync\tests\fixtures\itgmania-fonts
```

Regeneration is an explicit reference update. Review the fixture diff and the
ITGmania revision recorded in `_manifest.json` before accepting it.

## Noteskin probes

`noteskin` loads one skin through ITGmania's `NoteSkinManager`. The probe uses
the same recursive fallback merge, `NoteDisplay` metric fallback, native
string/integer/float/boolean conversions, filename prefix matching, and
`.redir` traversal as the game.

```powershell
.\target\debug\itgmania-harness-rs.exe noteskin `
  vendor\itgmania\NoteSkins dance default
```

`noteskin-baseline` probes all 28 selectable skins bundled with ITGmania
(dance, pump, techno, and lights) and writes one JSON fixture per skin plus a
provenance manifest:

```powershell
.\target\debug\itgmania-harness-rs.exe noteskin-baseline `
  vendor\itgmania\NoteSkins `
  --out ..\deadsync\tests\fixtures\itgmania-noteskins
```

The manifest contains a portable source snapshot. It preserves every resource
path and the exact text of `metrics.ini` and `.redir` files; image, model, and
Lua files become zero-byte placeholders because this parity slice only needs
their filesystem identity. DeadSync reconstructs that tree in a temporary
directory and checks discovery, all authored metric keys and typed values, and
canonical/discovered element paths on Windows or Linux without loading the C++
oracle. A second test checks the 25 ITGmania skins currently shipped by
DeadSync directly from `assets/noteskins`.

This is deliberately a loader-level oracle. It does not yet execute and
serialize noteskin Lua actor tables, decode textures, or compare rendered
pixels; those outputs require a separate actor/render fixture schema.

## Song Lua probes

`song-lua` loads one simfile through ITGmania and records every entry in
background layers 1 and 2 and the foreground. The native output preserves
layer/index order, start beat, playback rate, effect, transition, both files,
and both colors. Rust only resolves which native file references lead to Lua
entrypoints.

```powershell
.\target\debug\itgmania-harness-rs.exe song-lua `
  "..\lua-songs\Delightful Day\Delightful Day.ssc"
```

`song-lua-baseline` recursively probes all `.sm`, `.sma`, `.ssc`, and `.ats`
simfiles in a corpus. It writes one JSON fixture per simfile and a provenance
manifest. The current `lua-songs` corpus produces 43 simfile fixtures with 52
referenced Lua entries:

```powershell
.\target\debug\itgmania-harness-rs.exe song-lua-baseline `
  ..\lua-songs `
  --out ..\deadsync\tests\fixtures\itgmania-song-lua
```

DeadSync's always-on native test compares Lua layer discovery, start beats,
paths, and native ordering across the entire corpus:

```powershell
cd ..\deadsync
cargo test --test song_lua_itgmania_parity `
  itgmania_song_lua_layer_discovery_matches_deadsync
```

The bounded compatibility sweep executes initialization and the first ten
seconds of every unique DeadSync Lua session, aggregates all errors, and takes
about two minutes in a debug build. It is explicit because the corpus currently
contains known compatibility gaps:

```powershell
cargo test --test song_lua_itgmania_parity `
  lua_song_corpus_smoke_compiles_in_deadsync -- `
  --ignored --nocapture --test-threads=1
```

An additional ignored test, `lua_song_corpus_fully_compiles_in_deadsync`,
samples every complete song and is intended for deliberate long-running parity
runs.

The discovery fixtures find missing or misordered Lua files, but do not describe
what those scripts do. `song-lua-semantic-baseline` is the headless behavioral
oracle. It compiles ITGmania's bundled, patched Lua 5.1 runtime into the harness
and evaluates every referenced layer in-process. It never launches, patches, or
rebuilds an ITGmania executable.

```powershell
.\target\debug\itgmania-harness-rs.exe song-lua-semantic-baseline `
  ..\lua-songs `
  --out ..\deadsync\tests\fixtures\itgmania-song-lua
```

The default deterministic context enables both dance-single players, selects a
Challenge chart when available, and runs the actor tree on a deterministic 60
Hz clock using the chart's native BPM segments. It retains render samples on
the first update at or after each quarter beat through the later of the chart's
last note and its native `LASTSECONDHINT`, and permits 500,000 semantic events
per simfile. `song-lua` discovery wire version 2 exposes the specified last
second and beat from the native Song loader and timing conversion.
Use `--until-beat N` to extend the minimum endpoint for additional outro and
quiet-frame checks; it cannot shorten the authored endpoint. Override sampling
and event bounds
with `--beat-step` and `--max-events`. A runtime error or event limit marks that
fixture `partial`; the command still writes its usable trace and records the
exact error or dropped count in `_semantic_manifest.json`.

Use repeatable `--simfile relative/path.ssc` arguments to retry selected files.
Selections must resolve to simfiles inside the corpus; duplicates run once.
Charts with no Lua references produce complete empty actor captures, so their
original simfiles can still be archived.

The host passes all `LoadActor` arguments, initializes children before their
parents, and dispatches `BeginCommand` before `OnCommand`. Player option
getters use the linked native Lua bindings, including approach-speed return
values. The pinned fallback theme helpers execute unchanged and their hashes
are recorded in `theme_reference`. The calendar is fixed to October 1, 2026
at noon and recorded in the trace. Song reseeds are retained; native seed zero
uses wall time and is marked unreproducible in the archive.

Self-queued recurring commands execute at every 60 Hz update. Their repeated
operation observations use the same `--beat-step` cadence as update callbacks;
initialization, audio loads, and boolean changes remain observable. This
bounds repeated animation traces without reducing the execution cadence.
`trace_until_seconds` records the native endpoint used by the scheduler;
native beat/time conversions do not necessarily round-trip to the same beat.

RageFile reads and directory listings access the real corpus. Archives retain
successful file-read and listing dependencies, including non-Lua data files.
Writes are disabled by default. To capture a song that generates its own data,
copy it into an isolated corpus and set `ITGMANIA_SONG_LUA_WRITE_ROOT` to that
corpus for the capture process. Writes must resolve inside the selected song
folder. The trace records generated reads and writes, and generated Lua is
excluded from the original source closure. Archive against the original
corpus to preserve the input files. Native music-length queries support Ogg
Vorbis and WAV via ITGmania's unchanged readers; other formats report an error.

Use `--steps-type dance-double --difficulty Challenge` to capture a double
chart explicitly. An explicit steps type requires a chart with that style
and difficulty; it does not fall back to another chart. The selected style
is recorded in the manifest and trace.

For invalid indexed confusionoffset/movex/movey `FromString` writes, events
retain native no-op evidence and queried affected fields. Native indices are
1 through 16; index 0 or 17 does not create an additional modifier. The local
fixture checks unchanged nonzero values, and the semantic audit compares the
queried global/active-column fields rather than the invalid requested level.

Use `--random-seed N` to select reproducible native random inputs. The
default remains 1; seeds must be in `1..=2147483647` because native seed 0
uses wall time. The manifest, trace and session cache retain the exact
seed. Preserve failed captures when selecting an additional seed to
exercise a song's successful execution.

Audio `LoadActor` paths use the fallback theme's `Def.Sound` definition,
including extensionless `.mp3`, `.oga`, `.ogg`, and `.wav` paths. They are
excluded from drawable geometry rather than represented as sprites.

`Song:GetAllSteps()` and `Song:GetStepsByStepsType()` enumerate the charts
loaded by ITGmania, retaining native order, descriptions, difficulty and
steps-type enum names, and meters. Their Steps objects are shared with
`GAMESTATE:GetCurrentSteps()`, so scripts can identify the selected chart by
equality. Each enumeration returns a fresh array. Type queries use native
enum validation. Synthetic Lua-only test contexts retain one selected chart.

`TimingWindowAdd` preference reads and writes retain the native float value
within each capture, including save-and-restore scripts such as Mawaru9.
Other preference writes remain explicitly unsupported.

The instruction guard applies to loading and to each replay frame separately,
so finite 60 Hz bookkeeping does not exhaust a whole-song quota. A runaway
callback is terminated and recorded as a runtime error with its song beat.
Exhaustion outside a protected callback still fails capture.

Column spline objects use the linked ITGmania `CubicSplineN` implementation
and its Lua bindings, including bounds checks, vector copies, resize defaults,
solving, getters and evaluation. Session-owned native objects use the three
dimensions and actor ownership set by `NCSplineHandler`; the wrapper maps
camel aliases as `_fallback/Scripts/01 alias.lua` does. Setter traces retain
the existing sampling cadence. This does not replace the surrounding
headless NoteColumn actor scaffolding.

The current 43-simfile corpus completes with no partial or failed entries. Each
compact fixture contains:

- the returned `Def.*` tree, exact background/foreground root order, actor
  classes, properties, commands, and source lines;
- grouped command runs and beat/time samples for messages and modifiers;
- callback operation tracks for per-frame actor, player-option, and spline
  mutations without repeating context on every sample;
- render-sensitive state calls for position, scale, X/Y/Z rotation, skew,
  perspective, crop, visibility, and alignment at every sampled beat;
- external `ScreenGameplay` actor paths plus Player visibility tracks that
  distinguish the hidden source Player, visible `ActorProxy` instances, and
  the effective rendered notefield;
- explicit immediate, sleep, tween, and queued-command tracks, including their
  ordered destination mutations;
- stable source-derived child draw order and `z_position_each_draw` labels;
- the source-derived ITGmania actor transform order and menu-perspective model,
  with the exact C++ source files recorded as provenance;
- projected Sprite geometry as local/world corners, homogeneous clip vertices,
  screen coordinates, texture dimensions, and the active camera. Homogeneous
  coordinates preserve the cases where ITGmania clips a triangle at the camera
  plane instead of discarding the whole actor;
- structured runtime errors, event counts, and capability flags.

This records semantic causes and values, not screenshots. The binding surface
models the engine objects needed by the corpus while the parser, bytecode, Lua
language behavior, and StepMania `cmd(...)` syntax come from ITGmania's checked-
out runtime. It does not claim native renderer output or private C++ actor-memory
inspection; those capabilities remain explicitly false in each fixture.

`zoomtowidth` and `zoomtoheight` set destination zoom axes using the unzoomed
actor dimensions, including pending tweens. Zoomed-size getters include base
scale and destination zoom. The `zoom-axis-fit` fixture compares these fits
and later zoom resets against compiled native `Actor::ZoomToWidth` and
`Actor::ZoomToHeight` calls. Regenerate affected semantic fixtures after this
correction: older captures recorded these fit calls without applying them.

Actor color arguments use ITGmania's `RageColor::FromStackCompat` directly.
Legacy `diffuse(r,g,b,a)` and color tables both update one RGBA tween state;
`diffusealpha` replaces its alpha, and `diffusecolor` changes RGB while retaining
alpha. `GetDiffuseAlpha` reads the tween destination; projected samples read
the current color, including ancestor alpha. Harness 0.1.8 preserves NaN and
both infinities in render-state alpha with typed number tags instead of
JSON null. Compression compares the raw values before serialization; repeated
NaNs do not create a spurious sample on every frame. Older captures containing
null alpha need regeneration for exact nonfinite comparison. Background brightness uses the
numeric 0.7 default from `Background.cpp`. Regenerate semantic fixtures after
changing this model: previous captures discarded numeric color arguments and
could retain stale alpha after later `diffuse` calls. Run native headless tests
with `--test-threads=1` because they use ITGmania's global managers.

DeadSync has an always-on test for corpus completeness and the no-executable
contract:

```powershell
cd ..\deadsync
cargo test --test song_lua_itgmania_semantic_parity `
  semantic_fixture_manifest_is_complete_and_headless
```

The ignored parity audit compares a selected fixture's layer order, messages,
modifiers, message-command effect blocks, and every render-sensitive
`UpdateCommand` state sample with DeadSync while aggregating all known gaps.
DeadSync also checks its actor rotation, nested-center, and perspective math
against the source-derived ITGmania conventions. This catches state and
projected-geometry errors such as a same-beat center reset being overwritten or
X/Y rotations using the wrong handedness.

```powershell
cargo test --test song_lua_itgmania_semantic_parity `
  native_song_lua_semantics_match_deadsync -- `
  --ignored --nocapture
```

Set `ITGMANIA_SONG_LUA_TRACE` to another generated semantic fixture and
`ITGMANIA_SONG_LUA_SIMFILE` only if its source simfile can no longer be located
uniquely. The older `song-lua-trace` command remains available for an explicit
full-game `ScreenGameplay` investigation, but it is not used to generate or
verify this corpus.

### Compressed whole-song archives

`song-lua-archive` packages each complete semantic fixture as one deterministic,
content-addressed `.tar.zst`. It reads the semantic corpus generated above and
does not launch ITGmania:

```powershell
.\target\debug\itgmania-harness-rs.exe song-lua-archive `
  ..\lua-songs `
  --traces ..\deadsync\tests\fixtures\itgmania-song-lua `
  --out ..\deadsync\tests\fixtures\itgmania-song-archives
```

Each archive contains `manifest.json`, the simfile, the executed Lua source
closure plus statically referenced Lua dependencies, locally reachable assets,
and the complete compact semantic/render trace. The manifest records schema and
ITGmania revisions, display/update/random-state context, texture dimensions and
sprite grids, required asset references, and the SHA-256 and size of every
member. The archive filename is the SHA-256 of the compressed bytes; `index.json`
maps source charts to those hashes.

DeadSync opens archive files normally, verifies their content addresses, and
stream-decompresses them into isolated temporary song directories. Archive bytes
are deliberately not embedded into the test executable.

The remaining hard boundary is rasterization: the fixture contains projected
geometry but not GPU texture sampling, shader output, or final pixels.
`projected_vertex_samples` is true for fixtures that produce drawable projected
Sprites; `raster_output` remains false instead of implying pixel-perfect
coverage that the headless oracle does not provide. Native private tween-queue
memory inspection also remains outside the no-launch oracle; ordered semantic
tween destinations are recorded instead.

## Output notes

### Whole-corpus candidates

The published RSSP baseline contract uses engine timing/radar/tech statistics
and the selected Simply Love version's hash, density, NPS, and stream output.
Older Simply Love calculates NPS in Lua double precision; current Simply Love
uses ITGmania's float NPS cache. These are different reference contracts, even
after identical six-significant-digit serialization. Pin the actual script
files used by the earlier baselines when regenerating that contract. Raw engine
data always remains available in the native document.

`charts SIMFILE --theme PATH --out capture.json.zst` writes a compressed native
document and prints a small capture summary. Partial theme results remain
explicit in the document; this inspection command does not certify them as
complete manifest baselines.

Unknown native chart types are preserved with `note_data_supported=false`,
empty note/statistics collections, and null first/last times. Supported charts
in the same simfile are still captured. The RSSP dance parity adapter excludes
those unsupported extra charts; strict manifest baselines reject them.

Non-UTF-8 song metadata is preserved as `{ "raw_bytes_hex": "..." }` with
`metadata_utf8=false`. Chart references remain available. The parity adapter
reports an explicit metadata-encoding failure without guessing displayed text.

Generate a separate corpus with isolated child processes and a durable journal:

```powershell
python scripts/corpus_baselines.py C:/path/to/packs `
  --harness target/release/itgmania-harness-rs.exe `
  --theme vendor/simply-love `
  --out C:/path/to/candidates --jobs 3
```

Add `--resume` to continue with the same executable and theme. A deliberate
`--upgrade-harness` records the prior executable configuration and preserves
completed captures; use it only for changes that leave reference values
unchanged. Every new journal entry pins its executable digest. Failed, crashed,
or timed-out inputs remain unavailable, with no repaired source or fallback
values. Both compressed and uncompressed `.sm`/`.ssc` inputs are scanned.

The rework RSSP `all_parity` test accepts `RSSP_PARITY_PACKS_DIR`,
`RSSP_NATIVE_BASELINE_DIR` (the candidate root), `RSSP_PARITY_BASELINE_DIR` (the
existing RSSP-only references), `RSSP_PARITY_RESULTS` (JSONL), and
`RSSP_PARITY_QUIET=1`. `RSSP_PARITY_CASES_FILE` selects a JSON array of relative
simfile paths for a targeted rerun. Use `scripts/summarize_corpus.py C:/path/to/candidates`
after collecting `parity.jsonl` to write the report and failure CSV.
Native hash, timing, counts, tech and NPS are the primary
reference. Unchanged Simply Love supplies display text, spacing and breakdowns;
partial theme results cannot produce a full pass. The adapter applies the
RSSP report's existing numeric formatting while preserving raw candidate data.
All comparison categories run for each available input, so one mismatch does
not hide another category. Existing RSSP-only metrics retain their independent
regression references and are never regenerated from the code under test.

To generate the original baseline format without changing the RSSP consumer,
add `--rssp-baseline DIR` to `charts`. It writes `DIR/MD5-prefix/MD5.json.zst`
using the original uncompressed input's MD5 and the old CLI's numeric/text
serialization. Invalid UTF-8 display metadata follows the previous CLI's
explicit Windows-1252 policy; exact bytes remain in the native capture.
Incomplete theme data cannot create a report and clears a stale report for that
input. With `--out`, the capture summary records the reason in `rssp_error`.

Use `--rssp-reference C:/path/to/existing-baselines` with `corpus_baselines.py`
to generate native captures and these legacy-format reports together, copying
existing RSSP-only references unchanged. Then run the existing test binary:

```powershell
python scripts/run_corpus_parity.py C:/path/to/candidates `
  --test-bin C:/path/to/all_parity.exe --out C:/path/to/results
```

The runner verifies source digests, builds a read-only test input view (compressing
uncompressed extras), and runs the test in its original baseline mode. It does
not patch RSSP. By default, missing RSSP-only references remain missing.

The selected theme is part of the reference contract. To reproduce the previous
harness's baselines, explicitly select its unchanged Simply Love scripts. Recent
themes can use native float NPS where the earlier scripts use Lua doubles, and
native density/hash inputs can differ from the theme's raw simfile inputs.
The legacy report uses actual selected-theme NPS, density, hash, and stream
results, while retaining current engine statistics and timing. Script digests
are recorded; the harness never silently switches theme versions.

Some extra files may have no historical references for RSSP-only calculations
such as matrix ratings and pattern counts. Record those separately, if needed:

These explicitly marked RSSP-derived seeds allow the existing consumer to reach

They contain no engine/theme expected values. The seed manifest pins source and
executable digests, and the runner records every file that used a seed.

`--theme-repairs MANIFEST.json` accepts explicit, SHA256-pinned theme-only

must reproduce the original chart's engine note data, timing, BPM ranges,
statistics, native hash, and first/last times exactly, with no tolerance. Only
its complete theme result is imported; original metadata and engine values are
retained. `theme_repairs` records every applied copy in the native document.

accepts a separate capture directory containing those audited recaptures.

Chart selectors compare the exact `Steps::m_StepsTypeStr`, native difficulty
enum code, and exact description. They fail when zero or multiple charts match;
use `--index` when identical chart identities are intentionally present.
An unqualified `chart` command also requires exactly one chart. Each capture
retains its zero-based `source_index`, including after selection.

Chart captures use ITGmania's direct simfile loader with caching disabled.
Both the native loader and Lua read an isolated snapshot of the same input
bytes. `.sm.zst` and `.ssc.zst` corpus files are decompressed without changing
the original. `source_sha256` identifies the decompressed bytes. This captures
the charts initially loaded in memory; it does not claim to reproduce the
full game's later compression and lazy reload behavior.

With `--theme`, the harness loads `SL-ChartParser.lua`,
`SL-ChartParserHelpers.lua`, and `SL-BPMDisplayHelpers.lua` unchanged. Native
Steps, timing, tech counts, and file/hash bindings supply their inputs. The
document records the three script SHA-256 digests and the host digest. Results
under each chart's `theme` include both players' stream data, 16-note stream
sequences, all four breakdown levels, and `StringifyDisplayBPMs()` output at
music rate 1. Native floats remain unrounded; theme strings retain their actual
formatting, and Lua numbers retain Lua's double precision.

Theme captures have `complete`, `partial`, or `unavailable` status and explicit
errors. Inspection keeps partial results; baseline generation rejects them.
No empty or failed theme hash is replaced by the engine hash. Duplicate native
type/difficulty identities are ambiguous for Simply Love; Edit charts also
compare description. A distinct native ordinal does not repair the theme's
first-match behavior. Themes without the requested functions are unavailable
or partial, rather than silently using another version's parser.

## Baseline manifests

Manifest paths are resolved relative to the manifest file. A case may use an
index or an exact native-identity selector:

```toml
version = 2
theme = "vendor/simply-love" # omit for engine-only capture

[[case]]
name = "challenge-chart"
simfile = "fixtures/song.ssc"
steps_type = "dance-single"
difficulty_code = 4
description = "Exact edit description"
expected_chart_count = 3 # coverage of the complete simfile, before selection
```

Use `all_charts = true` instead of selectors to capture a whole simfile; version
2 requires `expected_chart_count` for that capture. Version
1 manifests remain readable. Semantic selectors and ordinal selectors cannot
be combined; missing selectors never silently choose the first of several
charts. Empty manifests and simfiles with no loaded charts are errors.

An oracle-only repair is an explicit, separately maintained copy. Add
`oracle_simfile`, a nonempty `repair_reason`, `original_sha256`, and
`oracle_sha256` to the case. Both digests must match the decompressed bytes;
obtain them from `charts` output. The output keeps the original `simfile` key
and records the repair path, reason, and both digests. Neither input is edited.
This allows an original that RSSP accepts to remain the parser test input while
ITGmania and the theme read the reviewed oracle copy. Selecting a repair does
not prove that it preserves gameplay; that remains a per-song review decision.

Native loader warnings and user diagnostics are retained. Generation requires
them to match `expected_diagnostics` exactly (default `[]`), validates native
hash/stat completeness and requested chart coverage, and rejects incomplete
theme results. These checks run for every case before any output is written.

`baseline` first loads and selects every case. Only after all cases succeed
does it write `<name>.json` files and `_manifest.json`. Each file is flushed to
a temporary file and atomically renamed into place. The sidecar records the
schema and harness versions, the ITGmania build root, Git revision and dirty
state, original/oracle digests and repair reason, and selected source ordinals
for each case. Source and theme digests also live in the individual documents,
so read-only verification detects changed inputs and scripts.

`verify` regenerates every selected case in memory through the ITGmania oracle
and compares it with the existing `<name>.json`. It never updates expected
files. `diff` compares any two JSON files without running the oracle. Both
commands compare parsed JSON values recursively and report stable paths such as
`$.charts[0].meter`; object key order and equivalent number spellings such as
`1`, `1.0`, and `1e0` do not create differences. Negative zero remains distinct
from positive zero because its sign is part of the transported native value.

## Build direction

The build has one user-facing entrypoint: `cargo build --release`.
ITGmania is C++, so a small native bridge is unavoidable. It will contain only
ABI conversion and calls into ITGmania; the CLI, schema, baseline orchestration,
diagnostics, and output are Rust-owned.

Native oracle calls are serialized because ITGmania's singleton managers and
diagnostics share process state. Difficulty conversion comes from ITGmania's
`Difficulty.cpp`, including its aliases and enum strings.

The minimal runtime scaffolding is owned by this project. It supplies singleton
services and application context for the linked native classes. That context
is part of the capture contract: defaults must match the checked-out engine
and theme before native results can establish parity. The native classes
compute the measured behavior; unsupported services remain coverage gaps.

Real simfiles use native `TimingData` for the song clock, including charts
with only BPM segments. This matches `SongPosition` float arithmetic and
keeps global song timing separate from chart timing. These captures report
`song_clock: native-song-timing`; synthetic actor-only inputs retain the
continuous BPM fallback. Captures made before harness 0.1.5 can retain a
double-precision clock for simple charts and should be regenerated when
strict beat boundaries are relevant.

`ActorFrame:SetUpdateRate` follows both parts of the native API: the Lua
binding requires a numeric argument and raises for nonpositive native floats;
the C++ setter stores only strictly positive rates. Harness 0.1.9 therefore
preserves the existing rate for NaN, including its zero-delta startup update.
Earlier NaN-rate captures need regeneration.

Song Lua captures load the bundled Cyber noteskin through native
`NoteSkinManager` by default. `ITGMANIA_SONG_LUA_NOTESKIN_ROOT` and
`ITGMANIA_SONG_LUA_NOTESKIN` override its root and name. The trace pins the
resolved metrics, Lua templates, and resource hashes. Harness 0.1.10 removes
the placeholder sprites and zero metrics previously used when no noteskin
root was supplied; captures that used those substitutes need regeneration.
Missing noteskin resources produce a diagnostic error.
Both native players select that skin through the actual `PlayerOptions`
binding before song Lua runs. When comparing against another runtime, set
the root to the exact resource copy that runtime consumes; optimized PNGs
can have different hashes despite sharing Lua templates and dimensions.
For DeadSync captures in this workspace:

```powershell
$env:ITGMANIA_SONG_LUA_NOTESKIN_ROOT = "C:/GitHub/deadsync/assets/noteskins"
```

Harness 0.1.13 retains `noteskin_option` details for `FromString`,
`PlayerState.SetPlayerOptions`, and direct `NoteSkin` writes on every frame,
including unsampled calls. Previous/current values come from the linked native
getter. A copy of the native parser identifies the exact string parts that
select skins without mutating live options or rerunning random modifiers.
These are string settings, separate from numeric modifier targets. The native
Common default metric and Lua theme query both use `cel` from Simply Love's
`metrics.ini`; the initially selected profile skin can still be Cyber.
An explicit-nil native getter avoids the optional-chaining macro's invalid
zero argument index after setters. Older captures lack this string evidence
and need recapture to audit noteskin changes independently.


Harness 0.1.15 records effects from each direct wrapper in the projected
effect chain, as Actor::Draw applies its wrapper stack through PreDraw and
BeginDraw. The trace reports wrapper_effects = native-draw-stack. Older
captures omit these entries and must be regenerated when wrapper vibration
is audited. The native Actor drawing regression verifies the same vibration
envelope independently of the headless trace.
